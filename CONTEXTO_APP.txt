MotoRide app - Contexto y registro de cambios
Ultima actualizacion: 2026-04-13

Objetivo del archivo
- Mantener el contexto funcional y tecnico de la app.
- Registrar los cambios importantes que se hagan en cada sesion.
- Facilitar migrar el proyecto a otro PC sin perder conocimiento.

Resumen funcional de la app
- App para salidas grupales en moto.
- Permite crear o unirse a rutas de grupo.
- Muestra la ubicacion de usuarios en tiempo real durante la ruta.
- Permite comunicacion por voz entre participantes (chat de voz).
- Incluye alertas rapidas (averia, repostar, parado, etc.).

Stack y arquitectura general
- Frontend: React + TypeScript + Vite.
- UI: Tailwind CSS + iconos/librerias de interfaz.
- Realtime: Socket.IO (cliente/servidor).
- Auth y datos: Firebase Auth + Firestore.
- Mapa: Leaflet / React-Leaflet.
- Voz: WebRTC (simple-peer) con senalizacion via Socket.IO.
- PWA/offline parcial: service worker y manifest.

Flujo principal actual
1) Usuario inicia sesion con Google.
2) Crea ruta o se une por codigo/enlace.
3) Entra a la vista de mapa del grupo.
4) Se activa geolocalizacion y envio de posicion en tiempo real.
5) El servidor redistribuye posiciones/alertas a la sala del grupo.
6) Participantes pueden hablar por voz via WebRTC.
7) Al finalizar, se actualizan puntos/estadisticas segun logica de app.

Observaciones tecnicas importantes (estado actual)
- No existe chat de texto dedicado; hay voz + alertas.
- Existen server.ts y server.js (posible duplicidad de backend).
- Hay posibles inconsistencias entre groupId y code segun modulo.
- No se detectaron tests automatizados para modulos criticos.
- README podria no reflejar completamente la implementacion actual.
